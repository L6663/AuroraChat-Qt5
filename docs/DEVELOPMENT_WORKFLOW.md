# 开发与托管工作流

## 分支约定

- `main`：对外展示和阶段性稳定版本
- `develop`：日常集成与联调
- `feature/*`：独立功能
- `fix/*`：缺陷修复

## 提交约定

```text
feat: 新功能
fix: 缺陷修复
refactor: 重构
ui: 界面与交互调整
docs: 文档
build: qmake 与构建调整
test: 测试
```

## 发布门槛

进入 `main` 前至少完成：

1. Qt 5.4 本地编译通过；
2. 对应功能人工验收；
3. 正常流程与异常流程测试；
4. 无新增原生风格弹窗；
5. 协议枚举、客户端处理和服务端处理保持一致；
6. 数据库升级兼容旧数据；
7. README、路线图和已知问题同步更新。

## 当前协作方式

- 用户负责 Qt 5.4 本地编译和真实运行反馈；
- 项目托管侧负责需求拆解、源码审查、协议与数据库设计、UI 一致性、缺陷修复方案、文档和 GitHub 版本管理；
- 每次反馈应提供截图、编译错误全文或复现步骤；
- 功能修复后同步记录到 Issue 和 Roadmap。
