# Managed Audit — UI、截图与文件传输

## 已确认的 UI 问题

项目曾在删除好友、移除群成员、退出群聊、解散群聊、退出账号、重连失败和强制下线等流程中使用原生 `QMessageBox`。Qt 5.4/MinGW 下，全局 QSS 无法可靠统一原生消息框，容易出现黑色面板、文字对比度不足、系统图标和英文 `Yes/No` 按钮。

处理策略：

- 新增 `AuroraConfirmDialog`；
- 主业务确认流程逐步移除 `QMessageBox`；
- 浅色和深色主题使用统一组件规则；
- 危险操作默认聚焦取消按钮，降低误操作风险。

## 已确认的截图问题

旧流程：

```text
隐藏主窗口
→ 截取整个桌面
→ 保存 PNG
→ 立即上传
```

问题：

- 无法框选区域；
- 高分辨率 PNG 可能超过文件限制；
- 临时截图未稳定清理；
- 多显示器场景未跟随鼠标所在屏幕。

处理方向：

- 使用 `ScreenshotOverlay` 提供区域选择；
- 双击或 Enter 确认，Esc 或右键取消；
- 默认 PNG，超过限制时再进行 JPEG 压缩；
- 成功、失败和取消后统一清理临时文件。

## 已确认的文件传输问题

客户端过去依赖本地 `QFile` 当前文件指针继续读取，而服务端会独立返回 `receivedSize`。异常响应或状态偏移后，两端位置可能不一致。

已调整为：

- 每次读取分片前，客户端根据服务端确认偏移量执行 `seek()`；
- 分片大小保持 48 KB；
- 当前桌面项目文件上限为 20 MB；
- 后续继续补齐超时、重试、校验和断线续传。
